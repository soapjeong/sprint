# ESP32 입면 온도 탐색기 펌웨어 (v7)

`sleep_temp_optimizer/sleep_temp_optimizer.ino` — 히터 PID 가온 +
MPU6050/MAX30102 기반 입면(SOL) 추정 + 세션별 최적 온도 탐색.

**대상 보드: XIAO ESP32-S3 + 전용 캐리어 보드(40x50mm, rev.A)**

## 핀 배치

실크 인쇄(D0~D10)가 아니라 GPIO 번호를 쓴다.
`D0=GPIO1  D1=2  D2=3  D3=4  D4=5  D5=6  D7=44  D8=7  D9=8  D10=9`

| 용도 | 실크 | GPIO |
|---|---|---|
| 히터 PWM (MOSFET 게이트) | D3 | 4 |
| NTC 서미스터 (ADC1) | D0 | 1 |
| I2C SDA / SCL | D4 / D5 | 5 / 6 |
| MAX30102 INT (미사용) | D8 | 7 |
| MPU6050 INT (미사용) | D2 | 3 |
| 배터리 전압 분압 | D1 | 2 |
| 충전 상태 STAT1 / STAT2 | D9 / D10 | 8 / 9 |
| 시작 버튼 | XIAO BOOT | 0 |

**ESP32-S3 주의**
- GPIO **26~37** 은 내장 플래시·PSRAM 이 쓴다. 여기에 배선하면 부팅 중
  워치독 리셋(`rst:0x8 (TG1WDT_SYS_RST)`)이 반복되고 스케치가 시작조차 못 한다.
- ADC 로 쓸 수 있는 건 **GPIO 1~10**(ADC1) 이다.
- **GPIO0 은 부팅 모드를 정하는 스트래핑 핀**이다. 이 보드는 여기 말고 남는 핀이
  없어 시작 버튼으로 쓰되, 딥슬립 기상에는 쓰지 않는다(기상 순간에 눌려 있으면
  다운로드 모드로 들어간다). 그래서 전원 종료는 딥슬립 대신
  **히터·센서를 모두 끈 대기 상태(SESS_OFF)** 로 간다 — 앱에서 바로 다시 시작할 수 있다.

## 센서 구성 (`HAS_MLX90614`)

지금 보드는 MLX90614 를 달지 않아 `0` 으로 두고, **NTC 하나로 제어와 안전 감시를
겸한다**. 그래서 기본값이 이렇게 조정돼 있다.

| | MLX 장착(1) | 미장착(0) — 현재 |
|---|---|---|
| PID 제어 입력 | 피부 온도(MLX) | 히터 표면 온도(NTC) |
| 절대 상한 (피부/히터) | 42 / 45℃ | **43 / 43℃** |
| 탐색 상한 | 40.5℃ | **40.0℃** |

> 기록에 남는 "목표 온도"는 이 구성에서 **피부 온도가 아니라 히터 표면 온도**다.
> 발표·논문에 쓸 때 그렇게 적어야 한다.

## 센서 이탈(폭주) 감시

단일 센서 구성의 진짜 위험은 과열이 아니라 **서미스터가 히터 필름에서 떨어지는**
경우다. 이때 온도는 "정상 범위"로 보이므로 상한 감시에 걸리지 않는데, PID 는 목표에
도달하지 못해 계속 최대 출력으로 민다.

- 출력이 `RUNAWAY_DUTY_PCT`(95%) 이상으로 `RUNAWAY_WINDOW_MS`(3분) 동안 유지됐는데
  제어 온도가 `RUNAWAY_MIN_RISE_C`(1℃) 도 오르지 않으면 센서 이상으로 본다.
- 판정되면 기존 FAULT 경로를 그대로 타서 히터가 차단된다(`STATE_FAULT_SENSOR`).
- 온도가 오르고 있거나 출력이 낮으면 감시 창이 다시 열린다.

## 세션 진행 순서

| 세션 상태 | 시점 | 센서 | 히터 | 동작 |
|-----------|------|------|------|------|
| `IDLE` | start 전 | **정지** | OFF | 대기 (MPU6050 sleep / MAX30102 shutdown) |
| `WARMUP` | start 후 0~20초 | 측정 시작 | **OFF** | 온도·움직임·심박 **모든 데이터를 폐기**(워밍업) |
| `RUNNING` | 20~50초 | ON | ON | 가온 시작 + 30초간 **안정심박수** 측정 |
| `RUNNING` | 50초~ | ON | ON | 입면 판정 (기준 심박 이하 + 무동작 20분) |
| `COOLDOWN` | 입면 확정 후 10분 | 생체 센서 **정지** / 온도 센서 ON | ON | 결과 저장 후 목표 온도로 가온 유지 |
| `OFF` | 가온 10분 종료 / 60분 타임아웃 | **정지** | **OFF** | 기기 종료(딥슬립) |

## 변경 요약

### 1. 안정심박수 자동 캘리브레이션 후 입면 판정
워밍업(20초)이 끝난 뒤 **30초 평균**을 이번 세션의 안정심박수로 저장하고,
입면 기준 = `안정심박수 - 10 BPM` 으로 판정을 시작한다.

- 입면 조건: 심박이 기준값 이하 **20분 연속 유지** + 같은 구간에 **움직임 없음**.
  (1분 에폭 단위로 평균 심박·누적 움직임을 판정하고, 20에폭 연속 만족 시 확정)
- 확정 시 호스트(서버)로 상태 플래그 전송: `@FLAG,<person>,SLEEP_ONSET,<millis>,<SOL분>,<안정심박>`
- 30초 동안 유효 비트를 못 얻으면 최대 3회 재측정하고, 그래도 실패하면 기본값(60 BPM)으로
  낮춘 뒤 움직임 위주로 판정한다(`@FLAG,...,HR_BASELINE_FALLBACK,...`).

### 2. 60분 미입면 시 기기 전원 종료
`SESSION_MAX_MS`(60분) 안에 입면이 확정되지 않으면 SOL을 60분으로 기록·저장하고
`@FLAG,...,NO_ONSET` / `@FLAG,...,POWER_OFF` 전송 후 **히터와 모든 센서를 끄고** 딥슬립으로 들어간다.
시작 버튼을 누르면 다시 깨어난다. 딥슬립 대신 대기만 하려면
`POWER_OFF_USE_DEEP_SLEEP` 을 `0` 으로 바꾼다.

### 3. 이상 온도는 5초 이상 지속될 때만 FAULT
- 과열/급상승/센서 이상이 감지되면 **히터 출력은 즉시 0**으로 끊되(`g_preFaultCutoff`),
  FAULT 래치는 같은 이상 상태가 `FAULT_PERSIST_MS`(5초) 이상 연속될 때만 한다.
- 5초 안에 정상으로 돌아오면 순간 노이즈로 보고 FAULT 없이 가온을 재개한다.
- 급상승(spike)은 감지 시점 온도를 기준으로, 온도가 0.5℃ 이상 내려올 때까지 이상 상태로 본다.

### 4. 모든 센서는 start 를 눌러야 측정 시작 + 20초 워밍업
- 부팅 시 센서를 검출한 뒤 곧바로 정지시킨다(MPU6050 `enableSleep`, MAX30102 `shutDown`).
  MLX90614 는 라이브러리에 `enterSleepMode()` 가 있는 버전이면 `MLX_HAS_SLEEP_API 1` 로 절전까지 수행하고,
  아니면 읽기를 멈춘다. NTC 분압 회로는 상시 전원이므로 ADC 샘플링을 멈추는 방식이다.
- start 후 `SENSOR_WARMUP_MS`(20초) 동안은 온도/움직임/심박 **모든 데이터를 버린다.**
- 이 구간에는 신뢰할 수 있는 온도가 없으므로 **히터를 켜지 않는다.** 가온은 워밍업이 끝난 뒤 시작하며,
  워밍업 직후 첫 샘플이 급상승(spike)으로 오판되지 않도록 직전값을 NaN 으로 비운다.

### 5. 60분 타임아웃 시 히터 + 모든 센서 정지
입면 없이 `SESSION_MAX_MS`(60분)가 지나면 히터와 모든 센서를 끄고 기기를 종료한다.

### 6. 입면 확정 시 — 생체 센서 정지 + 10분 가온 유지 후 전 계통 종료
`KEEP_HEATING_AFTER_ONSET` 기본값 `1`:

1. 입면 확정 → 판정에 쓰던 **생체 센서(MPU6050 / MAX30102)를 즉시 정지**하고 결과를 저장·전송
2. `HEATING_DURATION_MS`(10분) 동안 목표 온도로 **가온 유지**(`COOLDOWN`)
3. 10분 후 **히터와 온도 센서까지 정지**하고 기기 종료(딥슬립)

> 가온 유지 구간에서 온도 센서(MLX90614 / NTC)를 함께 끄지 않는 이유: 히터가 켜져 있는 동안
> PID 입력과 과열 감시(피부 42℃ / 히터 45℃ 컷오프)가 없으면 개루프 가열이 되어 화상 위험이 있다.
> 히터가 꺼지는 시점에 온도 센서도 함께 꺼진다.
> 입면 즉시 전 계통을 끄고 싶으면 `KEEP_HEATING_AFTER_ONSET` 을 `0` 으로 바꾼다(가온 유지 없음).

> FAULT 가 걸린 상태에서는 온도를 계속 감시해야 하므로, 세션을 abort 해도 `r` 로 FAULT 를 해제하기
> 전까지는 센서를 끄지 않는다.

### 7. 기기 ID 는 칩 MAC(efuse)에서 만든다
사람이 기기 번호를 정하거나 입력하지 않는다. 부팅 시 `esp_read_mac()` 으로 칩에 구워진
기본 MAC 을 읽어 `DORMX-246F28AABBCC` 형태의 ID 를 만들고, 다음 줄로 호스트에 알린다.

```
@ID,DORMX-246F28AABBCC
```

브리지는 이 줄을 보고 업로드에 쓸 기기 ID 를 자동으로 잡으므로 `--device` 옵션이 필요 없다.
시리얼로 `whoami` 를 보내면 언제든 다시 확인할 수 있다. 같은 칩이면 항상 같은 값이라
기기를 바꿔 꽂아도 데이터가 섞이지 않는다.

### 8. 미입면 원인 보고
60분 안에 잠들지 못하면 무엇이 막았는지 세어 두었다가 `NO_ONSET` 과 함께 보낸다
(1=심박이 기준보다 높음, 2=움직임, 3=센서/심박 데이터 부족, 0=알 수 없음).
관리자 화면의 "실패 원인" 칸이 이 값을 보여준다.

## 호스트로 보내는 상태 플래그

```
@FLAG,<person>,<flag>,<millis>,<v1>,<v2>
```
`SESSION_START` / `WARMUP_DONE` / `HR_BASELINE` / `HR_BASELINE_FALLBACK` / `SLEEP_ONSET` /
`COOLDOWN_START` / `NO_ONSET` / `SESSION_DONE` / `FAULT` / `POWER_OFF`

`serial_csv_logger.py` 가 `@` 로 시작하는 줄을 이벤트 로그(`logs/events_*.log`)에 기록한다.
